# 제품 기획

## 제품 정의

NVideo Studio는 Windows 사용자가 이미 보유한 로컬 자료를 작가·작품 단위로 정리하고 한 애플리케이션에서 열람할 수 있도록 만드는 개인 라이브러리 도구다. 이미지·만화·전자책과 영상의 탐색 경험을 연결하고, 계정·게시판·후원 확인을 온라인 서비스로 제공한다.

로컬 파일 자체를 서비스에 업로드하는 제품은 아니다. 현재 클라우드 경계는 회원 인증, 게시판 및 그 첨부 이미지, 후원 확인에 있다.

## 해결하려는 문제

| 사용자 문제 | 제품 대응 | 확인할 결과 |
| --- | --- | --- |
| 폴더가 많아 작품을 다시 찾기 어렵다 | 루트·작가·작품 계층, 검색·태그·정렬·묶음 | 원하는 작품에 도달할 수 있는가 |
| 파일 형식마다 프로그램을 바꿔야 한다 | 통합 Reader와 로컬 미디어 플레이어 | 지원 형식이 같은 흐름에서 열리는가 |
| 열람 후 원래 목록 위치를 잃는다 | 페이지·포커스·필터 저장 및 복귀 | 읽던 작품을 닫아도 위치가 유지되는가 |
| 큰 이미지 ZIP이나 긴 웹툰에서 화면이 무겁다 | 페이지 목록·웹툰 표시 범위 제한, 필요한 데이터 조회 | 큰 작품에서도 탐색이 가능한가 |
| 기능이 늘면서 배포 목적과 코드 책임이 흐려졌다 | 제품 범위 축소, 기능 모듈화, 선택적 빌드 | 배포본에 불필요한 코드가 없는가 |
| 피드백과 회원 상태를 앱에서 확인하기 어렵다 | 계정·게시판·후원 상태 통합 | 인증·권한이 서버 기준으로 일치하는가 |

문제는 제품 가설이다. 탐색 시간·이탈률·성능 개선 수치는 아직 사용자 실험으로 측정하지 않았다.

## 주요 사용자 시나리오

### 개인 자료 열람자

사용자가 소유한 폴더를 루트로 등록하고 스캔한다. 작가와 작품을 검색한 뒤 이미지·문서·영상을 연다. 열람을 마치면 책장 목록과 기존 설정으로 돌아온다. 오프라인 로컬 기능은 온라인 계정의 상태와 분리해 사용한다.

### 피드백을 남기는 회원

Google 계정으로 로그인한 후 질문·피드백·제안을 게시한다. 필요한 경우 비밀글을 선택한다. 서버는 작성자와 관리자의 권한을 검증한다. 일반 회원과 후원 회원의 차이는 현재 표시·후원 상태이며 관리자 권한과 연결되지 않는다.

### 개발자·포트폴리오 검토자

DEV에서 플러그인 관리와 릴리스 구성기를 열어 포함할 기능을 선택한다. 선택 결과를 JSON으로 내보내고 기존 빌더에서 프런트엔드와 네이티브 기능을 함께 제한한다. 메뉴 숨김과 실제 빌드 제외가 다르다는 점을 확인한다.

## 제품 범위

| 범위 | 현재 상태 |
| --- | --- |
| 로컬 책장·Reader·로컬 영상·멀티뷰·설정 | 구현, 사용자 기능 확인 진행 중 |
| Google 로그인·로그아웃·회원 정보 표시 | 구현, 실제 OAuth 확인 필요 |
| 게시판 CRUD·신고·비밀글·관리자 공지·리치 텍스트 | 클라이언트와 API 구현, 서비스 단위 테스트 확인 |
| Ko-fi 웹훅·후원 상태·회원 표시 | 구현, 실제 결제 운영 검증은 별도 |
| DEV 플러그인 관리자·커스텀 프로필 | 구현, 실제 화면에서 구성 JSON 변경 확인 |
| 이메일/비밀번호 가입 UI | 현재 UI에 없음, 관련 IPC도 비활성화 상태 |
| 댓글·답글 | 현재 게시판 API·모델·마이그레이션에서 완료 구현을 확인하지 못함 |
| 프로필 편집 | 조회·표시는 있으나 편집은 별도 과제 |
| 파일 동기화·온라인 콘텐츠 수집·원격 제어 | 현재 제품 기능이 아님 |

## 메뉴 구성

RELEASE는 로컬 책장, 게시판, 환경 설정, 내 계정을 제공한다. DEV는 여기에 플러그인 관리를 추가한다. 내 계정은 Core의 대화상자로 제공하므로 프로필 JSON에는 `nvideo.library`, `nvideo.board`, `nvideo.settings` 세 개의 메뉴 플러그인만 등장한다.

## 사용자 경험 원칙

1. 파일과 독서 기록을 보존한다. 기존 스키마의 과거 메타데이터는 즉시 삭제하지 않는다.
2. 목록의 위치와 Reader 설정을 일관되게 유지한다.
3. 긴 작업에는 진행 상태·취소·실패 정보를 제공한다.
4. 삭제·이동·외부 플러그인 신뢰 변경은 대상을 확인하는 조작으로 처리한다.
5. 로컬 기능과 온라인 회원 기능의 책임을 분리한다.
6. 배포본의 기능 범위를 컴파일과 명령 등록에서도 제한한다.

## 우선순위

| 우선순위 | 다음 확인·작업 | 완료 판단 |
| --- | --- | --- |
| P0 | 실제 영상 재생 잠금 오류 조사 | 재현 경로·원인·수정·회귀 근거 확보 |
| P0 | 일반 실행과 검증용 데이터 경로 확인 | 기존 루트·기록·설정이 올바른 경로에서 유지됨 |
| P1 | Google 로그인·세션·게시판 권한 수동 검증 | 취소·재시도·로그아웃·비밀글·공지 권한 확인 |
| P1 | 외부 바이너리 배포 라이선스 정리 | 출처·해시·빌드 옵션·고지·소스 제공 방식 확인 |
| P2 | 댓글·이메일 가입·프로필 편집 범위 재결정 | 현재 제품 요구사항에 포함할지 먼저 결정 |
| P2 | 실제 파일 규모별 성능 측정 | 측정 환경·표본·시간·메모리를 함께 기록 |

## 성공 지표 제안

최초 루트 등록 성공률, 작품 열기 성공률, Reader 복귀 위치 유지율, 재생 오류율, 스캔 취소 후 데이터 보존 여부를 우선 측정한다. 수집 기능은 현재 별도 구현되어 있지 않으므로, 처음에는 사용자 기능 테스트 기록으로 평가할 수 있다. 사용자의 파일명·경로를 원격 분석 데이터로 자동 전송하는 방식은 전제하지 않는다.
