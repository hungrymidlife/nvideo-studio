# 포트폴리오 사례 설명

## 한 문장 소개

기존의 복잡한 데스크톱 애플리케이션을 로컬 라이브러리·Reader·미디어·커뮤니티 중심으로 재구성하고, 기능 모듈과 선택적 빌드를 통해 개발자 도구와 사용자 배포본의 경계를 정리한 프로젝트다.

## 설명할 수 있는 문제 해결

### 1. 제품 범위를 코드·배포 경계까지 반영

화면에서 메뉴를 숨기는 데 그치지 않고 온라인 사이트·다운로드·원격 서버의 구현·IPC·Cargo feature·번들 경로를 제거했다. 개발자 관리 기능은 DEV에 남기고 RELEASE에서는 모듈과 네이티브 명령을 제외했다.

설명 근거는 프로필 JSON, `build.rs` 대조, Vite manifest 검사, 실제 실행 파일의 제외 IPC 검사다. 변경 전 production handler 정적 등록 수 121개에서 현재 89개로 줄었고 이 중 개발자 명령 9개는 RELEASE에서 제외된다. 이 개수는 전체 public API의 품질이나 보안 점수를 의미하지 않는다.

### 2. 기능 제거와 사용자 데이터 보존을 함께 처리

필요 없는 온라인 기능을 제거하면서 기존 SQLite의 파일 경로·작품 ID·열람 기록·과거 메타데이터를 급하게 DROP하지 않았다. 로컬 메타데이터 파서와 온라인 엔진의 사용처를 구분하고, Reader 복귀·파일 이동·스캔 보존 회귀를 유지했다.

### 3. 서로 다른 실행 모델 연결

React의 비동기 상태, Rust IPC, SQLite, Win32 네이티브 surface, 외부 미디어 엔진, OAuth 및 서버 권한 검증을 하나의 사용자 흐름으로 연결했다. 가장 어려운 부분은 라이브러리 사용 자체보다 상태·세션·창·스레드의 수명주기를 맞추는 것이다.

### 4. 인증·권한·후원 상태의 분리

Google 로그인, 게시글 작성자·관리자 권한, 후원 회원 표시를 같은 boolean으로 처리하지 않는다. OAuth 콜백 후 세션을 확인하고, 서버는 JWT와 DB 권한을 검증하며, 후원 여부는 검증된 계정과 결제 기록으로 판정한다.

### 5. 검증 과정에서 실제 이슈를 드러내기

초기 TypeScript 미사용 import, 빠진 원격 IPC 함수, 제거된 Dashboard·Hitomi·기존 빌더를 기대하는 테스트를 수정했다. 이어 실제 빌드 중 생성 EXE 감시로 Vite가 `EBUSY`를 내는 문제를 확인해 산출물 감시를 제외했다.

반면 사용자 재생에서 보고된 플레이어 잠금 오류와 별도 probe 로더 실패는 해결된 것처럼 설명하지 않는다. 자동 테스트와 실제 장치 검증의 차이를 공개하는 것도 엔지니어링 결과의 일부다.

## 검증 근거로 제시할 것

| 항목 | 제시할 자료 |
| --- | --- |
| 제품 이해 | 범위·사용자 흐름·우선순위 문서 |
| 설계 | Core/Plugin 경계, 데이터 경계, 패턴 적용 코드 |
| 구현 | Library ViewModel, 서비스, Registry, Auth·Board·Supporter 경로 |
| 안정성 | 자동 테스트 결과와 미완료 기능 테스트를 함께 기록 |
| 배포 | 소스 커밋·프로필·해시·self-test를 가진 manifest |
| 사업 사고 | 현재 후원 모델과 아직 구현하지 않은 확장 가설 |
| 책임 있는 공개 | 외부 바이너리 라이선스와 프로젝트 라이선스의 미결정 사항 |

## 짧은 발표 구성 예시

1. 로컬 자료 탐색·열람의 불편과 기존 앱의 복잡도를 설명한다.
2. 제품의 네 가지 사용자 메뉴와 DEV 전용 관리 화면을 보여준다.
3. 아키텍처 그림으로 로컬 SQLite와 온라인 서비스의 경계를 설명한다.
4. 한 사례로 Library 조회의 stale-response 방지 또는 Reader 복귀 포커스를 따라간다.
5. 다른 사례로 RELEASE에서 개발자 IPC가 사라지는 빌드 검증을 보여준다.
6. 재생 잠금 이슈와 라이선스 과제를 포함해 다음 검증 계획을 설명한다.

발표 길이에 맞춰 사례를 선택한다. 기능을 전부 나열하는 것보다 문제 → 결정 → 코드 → 검증 → 남은 한계를 하나의 흐름으로 보여주는 편이 유용하다.

## 주장하지 않을 것

실제 측정하지 않은 속도·메모리·매출 수치, 모든 형식·장치에서의 무오류 재생, 전체 E2E 완료, 댓글·이메일 가입 UI 완료, 공개 재배포 라이선스 정리 완료를 주장하지 않는다. 코드·문서·빌드가 있는 것과 운영·실사용까지 검증된 것은 구분한다.
